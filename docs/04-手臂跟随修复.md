# G1_29 手臂跟随修复

修复于 2026-10-30 部署到机器人；2026-11-01 操作员确认跟随效果改善，体感延迟在一秒以内。该反馈是现场操作结果，不是经过时间戳测量的延迟指标。

## 原因与修改

旧发布器每周期都从实测关节位置重新限制目标。在 250 Hz、3 rad/s 的配置下，指令只能领先反馈 0.012 rad，使位置伺服驱动力持续很小。IK 又将目标限制在实测位置附近 0.1 rad，因此正常跟踪误差会反复触发截断。

新发布器从上一条成功下发的指令生成连续轨迹，分别限制速度、加速度和指令对实测位置的偏差。固定目标到达前进行制动；DDS 状态过期、写入失败或命令无效时，冻结或恢复最后有效轨迹。

IK 以之前有效解检查解的变化，以上一帧滤波结果进行热启动。重复输入仍经过滤波窗口；XR 位姿无效或求解失败时清除历史窗口和参考解。

默认参数：

| 参数 | 默认值 |
|---|---|
| `XR_ARM_VELOCITY_LIMIT_START` | 1.5 rad/s |
| `XR_ARM_VELOCITY_LIMIT_MAX` | 3.0 rad/s |
| `XR_ARM_ACCEL_LIMIT` | 10.0 rad/s² |
| `XR_ARM_TRACKING_ERROR_LIMIT` | 0.15 rad |
| `XR_IK_STEP_MAX` | 0.1 rad |

现有启动后 5 秒渐进加速仍保留，单次轨迹积分最多按 20 ms 处理。

## 使用与验证

启动方式不变：

```bash
cd ~/xr_teleoperate
./scripts/start_teleop.sh
```

连接头显后按 R 跟随，按 Q 退出。离线验证不会初始化真实控制器或创建机器人 DDS 发布者：

```bash
PYTHONDONTWRITEBYTECODE=1 ~/miniconda3/envs/tv/bin/python tests/test_arm_following.py
PYTHONDONTWRITEBYTECODE=1 ~/miniconda3/envs/tv/bin/python tests/verify_arm_following.py
```

11 项回归测试通过。真实 IK 与模拟 40 ms 关节响应联动，在 2 个模拟秒后左右腕位置误差约为 0.07 mm 和 1.27 mm；这组数据是离线仿真结果。

## 部署打包

ZIP 和 TAR.GZ 必须来自同一 Git 提交；项目中的 `dist/` 为忽略目录，压缩包不提交到源码仓库。

打包遵循现有 `xr_teleoperate_v1.0.0_arm64.tar.gz` 的命名与目录规范：`应用名_v版本_架构`，根目录包含 `card-module.json`、`VERSION`、源码、SDK 及 `.deb-build` 安装模板。

```bash
node deploy/scripts/package_release.cjs
# dist/xr_teleoperate_v1.0.0_arm64.zip
# dist/xr_teleoperate_v1.0.0_arm64.tar.gz
```

开发机需要 Node.js。两个归档使用相同的部署文件，清单填入当前提交、构建时间、版本、arm64 架构与维护者。包内只保留根目录的一份部署清单，`.deb-build/card-module.json` 是构建输入。

遵循原部署包，本机现有模型缓存和 WebXR 证书可随本地压缩包分发；证书与私钥仍不提交到 GitHub。归档排除 `.git`、`.workbuddy-ai`、`temp`、`dist`、运行日志、PID、Python 缓存、editable 安装元数据和相机探测截图。

## 本地、GitHub 与机器人同步

同步范围包含源码、相机配置、资源、文档、测试和启动入口。逐文件使用 SHA-256 核对；打包压缩包、Git 元数据、运行日志、PID、Python/模型缓存、editable 安装元数据及本机 AI 工具记录各自保留。

`cam_config_client.yaml` 保留机器人当前有效的 RealSense 配置。根目录的 `start_camera.sh` 和 `start_teleop.sh` 转发到 `scripts/` 中的维护入口，传递全部参数。

SCAM SDK 的三个动态库随源码提交和归档。现场证书、私钥和探测生成的相机截图按忽略规则保留在设备上；部署包可包含现有证书与私钥。
