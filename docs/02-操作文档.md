## 2. 首次部署（可复现步骤）

以下命令在**开发机**上打包、在**机器人**上解压。本次实际就是这么做的。

### 2.1 开发机：打包

```bash
cd /d/code/project/autobot-guide-service/xr_teleoperate
tar --force-local -cf - \
  --exclude=.git --exclude=__pycache__ --exclude='*.pyc' \
  --exclude=.workbuddy-ai --exclude=temp --exclude=dist \
  --exclude=.deb-build --exclude='*.egg-info' \
  --exclude=g1_29_model_cache.pkl --exclude='.teleimager.pid' \
  . | gzip -1 > /tmp/xr_teleop.tar.gz
```

> Windows Git Bash 下 `tar` 会把 `C:/...` 当成远程主机，**必须加 `--force-local`**。

### 2.2 传输

```bash
scp -o Compression=no /tmp/xr_teleop.tar.gz unitree@192.168.2.203:/tmp/
```

实测：97 MB 压缩包，10.5 秒，约 10 MB/s。传完**务必比对 md5**：

```bash
md5sum /tmp/xr_teleop.tar.gz                       # 本地
ssh unitree@192.168.2.203 md5sum /tmp/xr_teleop.tar.gz   # 远端
```

### 2.3 机器人：解压

```bash
ssh unitree@192.168.2.203
mkdir -p ~/xr_teleoperate
tar -xzf /tmp/xr_teleop.tar.gz -C ~/xr_teleoperate
cd ~/xr_teleoperate
chmod +x scripts/*.sh third_party/dex1_1_service/bin/* deploy/scripts/*.sh
```

### 2.4 机器人：安装三个内嵌包

`dex-retargeting` / `teleimager` / `televuer` 是**随仓库分发的源码包**，必须 editable 安装一次（只需一次）：

```bash
source ~/miniconda3/etc/profile.d/conda.sh
conda activate tv
cd ~/xr_teleoperate

for d in teleop/robot_control/dex-retargeting teleop/teleimager teleop/televuer; do
  (cd "$d" && pip install -e . --no-deps --no-build-isolation)
done
```

> `--no-deps --no-build-isolation` 是刻意的：`tv` 环境里依赖已经齐了，加这两个参数可以完全离线安装，不会去拉 torch 之类的巨包。

### 2.5 验证部署

```bash
source ~/miniconda3/etc/profile.d/conda.sh; conda activate tv
cd ~/xr_teleoperate
export PYTHONPATH="$PWD/teleop/televuer/src:$PWD/teleop/teleimager/src:$PWD"

python -m compileall -q teleop scripts && echo COMPILE_OK
python -c "import teleop.robot_control.robot_arm as ra; print([n for n in dir(ra) if n.endswith('Controller')])"
python teleop/teleop_hand_and_arm.py --arm BOGUS    # 应报错并列出 7 个合法机型
```

期望输出：编译通过、8 个 Controller、`--arm` 报错信息里包含 `H2` / `R1_A5` / `R1_A7`。

## 3. 启动

脚本只有两个：`scripts/start_camera.sh`（相机）和 `scripts/start_teleop.sh`（遥操）。

### 3.0 相机服务（`start_camera.sh`）

负责头部相机画面。**自动探测，不需要手填配置**：

| 探测顺序 | 条件 | 结果 |
|---|---|---|
| 1 | 检测到 SCAM 双目相机（调 SDK 枚举，只认 `isExist` 的设备） | 用 `cam_config_server.yaml`，走 glibc-2.35 包装 |
| 2 | 没有双目，但检测到 RealSense 深度相机且 `pyrealsense2` 可用 | 用 `cam_config_server_realsense.yaml`，加 `--rs` |
| 3 | 都没有 | 生成「全部相机关闭」配置，**服务照常启动但不出图** |

```bash
bash scripts/start_camera.sh                # 前台启动（systemd 用这个）
bash scripts/start_camera.sh --detect       # 只探测，打印用了哪种相机
bash scripts/start_camera.sh --restart      # 重启
bash scripts/start_camera.sh --status       # 运行状态
bash scripts/start_camera.sh --logs 100     # 日志
bash scripts/start_camera.sh --find-camera  # 列出相机与 sysfs 路径（填 physical_path 用）
```

> 无相机时进程依然常驻，60000（配置查询）可用，只是 60001 不监听。部署器健康检查看的是进程存活，所以不会判红——现场相机坏了也能先把服务跑起来。

### 3.1 遥操作（`start_teleop.sh`）—— 现场手动启动（推荐，有终端）

```bash
cd ~/xr_teleoperate
bash scripts/start_teleop.sh
```

脚本会**先自动探测机器人上装了什么末端**（订阅 DDS 状态话题，见下表），
然后把探测结果作为菜单默认项 —— 直接回车即用：

| 探测依据 | 判定为 |
|---|---|
| `rt/dex3/{left,right}/state` 有数据 | 三指夹爪 Dex3-1 |
| `rt/inspire_hand/state/{l,r}` 或 `rt/inspire/state` 有数据 | 因时灵巧手 |
| `rt/brainco/{left,right}/state` 有数据 | 强脑灵巧手 |
| `rt/dex1/{left,right}/state` 有数据，或串口握手通过 | 两指夹爪 Dex1-1 |
| 都没有 | 无手（纯手臂） |

只看不说：`bash scripts/start_teleop.sh detect` 会打印 WiFi IP 和探测结论，不启动任何东西。

会先弹出末端选择菜单（括号内为探测结果）：

```
==================== 选择末端执行器 ====================
  1) 无手          —— 纯手臂遥操
  2) 两指夹爪      —— Unitree Dex1-1
  3) 三指夹爪      —— Unitree Dex3-1
  4) 因时灵巧手    —— Inspire
--------------------------------------------------------
  自动探测：两指夹爪 Dex1-1  → 直接回车即用
========================================================
请输入 1-4 [回车=2]:
```

选定后脚本继续做：

1. `conda activate tv`，设置 `PYTHONPATH`
2. 自动探测 `wlan0` IP 作为图像服务地址（可用 `IMG_SERVER_IP=...` 覆盖）
3. **仅当选 2（两指夹爪）时做夹爪体检**：服务是否已在跑 → 二进制是否可执行 → `/dev/ttyUSB*` 是否存在 → 用户在不在 `dialout` 组 → 跑一次 `--reset` 实际握手
4. 体检通过 → 拉起夹爪服务 + 给主程序带 `--ee dex1`；体检失败 → **自动降级为纯手臂模式**（不带 `--ee`），不会卡死
5. 前台启动主程序（`--arm G1_29 --input-mode <见下> --network-interface eth0 --motion`）

> `--input-mode` 由末端决定，不是固定值：选三指夹爪或因时灵巧手时必须是 `hand`，
> 否则主程序会直接报 `does not support controller input mode` 退出。脚本已自动处理。

跳过菜单直接指定末端：

```bash
bash scripts/start_teleop.sh --ee none      # 无手
bash scripts/start_teleop.sh --ee dex1      # 两指夹爪
bash scripts/start_teleop.sh --ee dex3      # 三指夹爪
bash scripts/start_teleop.sh --ee inspire   # 因时灵巧手
```

### 3.2 方式 B：远程 / 无终端启动

SSH 没有 TTY 时，键盘控制不可用，改用 IPC 通道：

```bash
bash scripts/start_teleop.sh start              # 后台启动（此时机器人不动，只等指令）
bash scripts/start_teleop.sh start --ee dex3    # 指定末端后台启动
bash scripts/start_teleop.sh control            # 等价于按 R —— 开始跟随
bash scripts/start_teleop.sh stop               # 等价于按 Q —— 清理并退出、手臂回零
bash scripts/start_teleop.sh status             # 输出 KEY=VALUE，供部署器解析
bash scripts/start_teleop.sh logs 100           # 看最近 100 行日志
```

> `start` 不传 `--ee` 时默认 `auto`：检测到可用夹爪就带上（`dex1`），否则纯手臂——与旧版行为一致，从控制台启动不会静默丢夹爪。

> `stop` 优先走程序自身的 `CMD_STOP` 路径（会执行 `ctrl_dual_arm_go_home`），**不要用 `kill -9` 或 `systemctl stop`**——那会跳过回零，手臂停在半空。

### 3.3 可选覆盖

```bash
IMG_SERVER_IP=192.168.2.203 bash scripts/start_teleop.sh   # 指定图像服务 IP
DISPLAY_MODE=ego bash scripts/start_teleop.sh              # 换显示模式
DEX1_NET_IF=eth0 bash scripts/start_teleop.sh              # 指定夹爪 DDS 网卡
CAM_KIND=realsense bash scripts/start_camera.sh            # 强制相机类型
```

## 5. 操作按键

| 按键 | 作用 |
|---|---|
| `R` | 开始跟随（同步机器人姿态到操作者当前姿态） |
| `S` | 开始 / 保存录制（`--record` 模式下有效，切换循环） |
| `Q` | 停止并退出，**会执行手臂回零** |

安全提示：按 `R` 之前确认机器人周围无人、手臂活动范围内无障碍物。程序启动后会打印：

```
🟢  Press [r] to start syncing the robot with your movements.
🔴  Press [q] to stop and exit the program.
⚠️  IMPORTANT: Please keep your distance and stay safe.
```

## 6. 服务管理

部署包注册两个 systemd 服务（**遥操主程序不在其中**）：

| 服务 | 作用 |
|---|---|
| `xr-teleimager` | 头部双目相机 WebRTC 图像服务（60001）+ `/status` 状态接口 |
| `xr-heartbeat` | 把本机 wlan0 地址上报给 `autobot-guide-service` |

```bash
systemctl status xr-teleimager
sudo systemctl restart xr-teleimager
systemctl status xr-heartbeat
```

安装 / 卸载：

```bash
sudo ./install_service.sh install   --root ~/xr_teleoperate
sudo ./install_service.sh uninstall --root ~/xr_teleoperate
sudo ./install_service.sh status    --root ~/xr_teleoperate
```

> `install_service.sh` 刻意**不生成** `xr-teleop.service`、不 enable、不 start 遥操主程序。这是硬性安全约束，不要绕过。

## 7. 故障排查

### 7.1 连不上 / 画面出不来

| 症状 | 可能原因 | 处置 |
|---|---|---|
| 头显打不开 8012 | 头显与机器人不在同一 Wi-Fi | 检查头显 Wi-Fi，确认能 ping 通 `192.168.2.203` |
| 打开后一直转圈 | 证书未信任 / televuer 未启动 | 确认主程序已启动；重新接受自签证书 |
| 画面黑屏但页面正常 | 相机未取到流 | `bash scripts/start_camera.sh --find-camera` 查相机；看 teleimager 日志 |
| 60001 不监听、服务却 active | 相机处于「半死」状态（USB 上还在但只枚举出 2 个 video 节点） | 服务停止时会自动复位（`ExecStopPost`）；手动复位：`sudo bash install_service.sh reset-camera`，仍不行再拔插 USB |
| 画面卡顿、延迟大 | 链路带宽不足 / 码率过高 | 降 `cam_config_server.yaml` 的 `bitrate` 或 `image_shape` |

### 7.2 遥操起不来

| 症状 | 可能原因 | 处置 |
|---|---|---|
| 一直刷 `Waiting to subscribe dds...` | 等不到 DDS 发布者（夹爪/手臂 lowstate） | 夹爪场景：确认夹爪服务在跑、`/dev/ttyUSB*` 未被占用；`sudo pkill -f dex1_1_gripper_server` 后重试 |
| 按 `R` 没反应 | 无 TTY（SSH 直连）/ 输入模式不匹配 | 改用 `start_teleop.sh start` + `control` |
| 提示 `--ee dex1_internal does not currently support --motion` | 参数冲突 | 去掉 `--motion` 或换 `--ee` |
| 提示 `dex1_internal is only supported with --arm G1_29` | 机型不匹配 | 换 `--arm G1_29` |
| `AttributeError: speed_gradual_max` | 用旧代码跑新机型 | 本次合并已修（加 `hasattr` 保护），确认代码是最新的 |

### 7.3 动作异常

| 症状 | 可能原因 | 处置 |
|---|---|---|
| 手臂持续慢跟随、`cmd_err` 长期卡在 0.1 rad | 旧版指令和 IK 每帧都以实测位置重新限幅 | 更新到连续轨迹修复版；先检查 `control_perf`，不要仅提高速度上限 |
| 手臂抖动 / 突然甩动 | IK 跳变（奇异位形、肘部翻转） | 看日志 `[ik-safety] IK joint step ... clamping`；必要时降 `XR_IK_STEP_MAX` |
| 夹爪合不拢 | 0.0 输入未映射（历史 bug） | 本次合并已修（首帧非零判定）；确认代码最新 |
| 夹爪不动 | 串口被占用 / 电机未上电 | `ls -l /dev/ttyUSB*`；`sudo pkill -f dex1_1_gripper_server` 重启 |
| 画面防抖方向反了 | EIS `axis_sign` 未标定 | 检查 `cam_config_server.yaml` 的 `stabilization.axis_sign` |

### 7.4 权限问题

| 症状 | 处置 |
|---|---|
| `Permission denied: /dev/ttyUSB*` | `sudo usermod -aG dialout unitree`，**重新登录**后生效 |
| `conda: command not found` | `source ~/miniconda3/etc/profile.d/conda.sh` |

## 8. 日志位置

| 日志 | 路径 |
|---|---|
| 遥操主程序 | 前台输出 / `start_teleop.sh logs` |
| dex1 夹爪服务 | `${TMPDIR:-/tmp}/xr_dex1_gripper.log` |
| teleimager | `systemctl status xr-teleimager` / `journalctl -u xr-teleimager` |
| 心跳 | `journalctl -u xr-heartbeat`；缓存 `last_heartbeat.json` |

关键日志前缀，便于 grep：

- `[ik-safety]` — IK 限幅告警
- `[arm-safety]` — 速度/加速度限幅、lowstate 陈旧
- `[xr_teleop][gripper]` — 夹爪体检与启动
- `[TeleVuer]` — XR 侧异常（渲染线程崩溃会打 traceback）
- `[Image Client]` — 相机
