## 3. 为什么不能直接 merge

本地与上游的**提交历史不相交**（unrelated histories）——本地历史上出现过一次 `Merge branch 'IMU' into integration/xr-unified (unrelated histories)`，导致 `git merge-base` 返回空。

直接 `git merge --allow-unrelated-histories` 的后果：git 会把两边所有不同的文件都当成"双方各自新增"，产生上百个假冲突，且无法区分"上游改了什么"和"我改了什么"。

实测对比：

| 方案 | 冲突数 | 是否可用 |
|---|---|---|
| 直接 merge（无共同祖先） | 上百 | ❌ 无法判断取舍 |
| 以 v1.5 为虚拟祖先做三方合并 | **27** | ✅ 每处冲突都有明确语义 |

## 4. 合并方法

### 4.1 虚拟共同祖先

本地代码基线就是上游 v1.5（README / CHANGELOG 停在 v1.5，代码无 H2/R1）。因此可以把 `v1.5` 当作"理论上的共同祖先"，对每个双方都改过的文件做三方合并：

```bash
git merge-file -p <本地版> <v1.5版> <上游版>
```

这样 git 能正确区分：
- 只有本地改的行 → 保留
- 只有上游改的行 → 采纳
- 两边都改的行 → 标记冲突

### 4.2 双父提交

合并结果不直接覆盖，而是构造一个**真正的合并提交**，父1 = 本地 HEAD，父2 = 上游 main：

```bash
tree=$(git write-tree)
commit=$(git commit-tree "$tree" -p HEAD -p refs/remotes/upstream-tmp/main -F msg.txt)
git reset --soft "$commit"
```

好处：**以后上游再更新，`git merge` 能正常工作**，不用每次重做虚拟祖先。

### 4.3 一个踩过的坑

`git merge-file` 是 Windows 原生程序，读不到 Git Bash 的 `/tmp` 路径（MSYS 路径）。第一版脚本因此**静默失败**：文件没被读取，输出为空，`grep` 数冲突得 0，得出"零冲突"的错误结论。

修复：临时文件改用 Windows 路径（`C:/Users/.../Temp/...`），并对返回码和冲突标记双重校验。

### 5.1 关键决策说明

**① `render_to_xr` 传参——采纳上游，这是真 bug**

`ImageClient.subscribe()` 返回的是 `TeleImage` 对象，不是 ndarray。本地代码 `tv_wrapper.render_to_xr(head_img)` 把整个对象传进 televuer，而 televuer 内部 `_xr_render_loop` 对它做 `cv2.cvtColor(latest_frame, ...)` —— 必然抛异常，被 `except` 吞掉后只打日志，表现为 **XR 画面永久冻结且无感知**。

上游 `79d95f0` 修的正是这个（传 `head_img.bgr`）。本地因为生产环境走 WebRTC（该路径被 `render_to_xr` 早退），ZMQ 显示路径从未被真正使用，所以这个 bug 一直没暴露。

采纳时额外加了 `head_img is not None` 判断（上游只判 `.bgr is not None`，若取帧返回 `None` 会 `AttributeError`）。

**② `speed_gradual_max` —— 加 `hasattr` 保护**

主程序无条件调用 `arm_ctrl.speed_gradual_max()`，但上游新增的 4 个类（H2 / R1_A5 / R1_A7 / G1_29_Arm_Internal_Dex1）没有这个方法。合并后如果不处理，切到新机型会直接 `AttributeError` 崩溃。

```python
if hasattr(arm_ctrl, "speed_gradual_max"):
    arm_ctrl.speed_gradual_max()
```

**③ 夹爪门控 —— 两个条件都要**

- 上游：`xr_motion_data_ready`（XR 动作数据到达前不动）
- 本地：首帧非零输入（`gripper_input_initialized`）

后者解决的是另一个问题：VR 数据就绪后，扳机按到底时输入精确为 `0.0`，若用 `if value:` 判断会停止映射，夹爪停在最后位置**永远合不拢**。两个条件是与关系，缺一不可。

**④ `set_arm_velocity_limit` —— 并存而非替换**

上游把硬编码的 `self.arm_velocity_limit = 30.0` 换成带校验的 setter；本地把它换成了安全常量 `ARM_VELOCITY_LIMIT_START`（1.5）。最终写法：

```python
self.set_arm_velocity_limit(ARM_VELOCITY_LIMIT_SIM if self.simulation_mode else ARM_VELOCITY_LIMIT_START)
```

既走上游的参数校验，又保留本地安全语义（仿真模式仍用 30 rad/s，避免仿真里动作过慢）。
